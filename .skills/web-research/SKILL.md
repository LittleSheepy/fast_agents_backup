# 网络调研（web-research）

把「用户的一句模糊提问」变成「一份有出处、可核验的调研报告」的标准作业流程。

## 一、适用与不适用

**该用**：需要外部信息的主题调研、现状梳理、多方对比、行业/市场/竞品调研、资料汇编。

**不该用**：
- 通用知识问答（模型本身答得出、且不需要出处）——直接回答，不要加载本技能；
- 需要实际计算或跑代码（改用 `python_calculator` / `terminal`）；
- 用户只要一句话结论，不需要成文材料。

## 二、执行流程

严格按 1 → 5 执行，不要跳步，尤其不要在第 2 步做完之前就开始写报告。

### 第 1 步 · 拆题
把用户请求拆成 3–6 个**可独立检索**的子问题，每个子问题写成一个具体检索词。
- ✅ `2026 年中国新能源汽车充电桩保有量`
- ❌ `新能源汽车 情况`

先确认范围与时效：主题、地域、时间范围、想要的产出形态。用户没给就用最合理的默认值，并在报告开头写明这个假设。

### 第 2 步 · 检索
对每个子问题调用 `web_search`，遵循：
1. **先泛后精**：先用宽泛词确认「最新对象是什么」（行业里最新的型号 / 政策 / 榜单），再针对出现的具体名称做定向检索。不要一上来就用记忆里的具体对象直接搜，容易搜到已经过时的东西而无从察觉；
2. **结论至少两个独立来源**；只有单一来源的，在报告里标注「单一来源，待核实」；
3. **来源分级**：官方网站 / 政府部门与统计机构 / 学术论文 / 企业一手公告 ＞ 主流媒体 ＞ 自媒体与论坛；
4. **记口径**：涉及数字时记下统计口径、单位和时间点；不同来源口径不一致就分别记录，不要混着用。

### 第 3 步 · 交叉核对
调用 `read_skill_reference` 读取 `source-check.md`，按其中的核验清单逐条检查关键结论，剔除或降级不达标的证据。

### 第 4 步 · 成文
调用 `read_skill_reference` 读取 `report-template.md`，按该结构输出。报告必须包含：
- 结论摘要（3–5 条，每条一句话）
- 分节正文（每条结论后面紧跟出处）
- 参考来源清单（序号 + 标题 + 链接 + 访问日期）
- 存疑与未证实事项

### 第 5 步 · 自检
交付前逐条打勾：
- [ ] 每个数字 / 结论后面都有来源
- [ ] 没有把「某自媒体的说法」写成「公认事实」
- [ ] 所有推断都显式标注了「推断」
- [ ] 关键数据标明了口径、单位与时间点
- [ ] 没有编造或拼凑来源链接

## 三、输出

默认输出 Markdown 正文。用户要求出文件时，用写文件工具落盘为 `调研报告-<主题>.md`，并回传文件路径。

模板与细则按需读取（不要一次性全读进来）：
- `report-template.md` —— 报告结构与写作示例
- `source-check.md` —— 来源可信度核验清单

## 四、注意事项

- **不许编造来源**：拿不到链接的结论，要么删掉，要么标注「未找到公开来源」。
- **事实与观点分开**：引用他人观点写「某某机构认为……」，不要当成客观事实。
- **检索失败要如实说**：多次检索仍无结果时写「该部分信息暂时无法获取」，不得用模型记忆冒充检索结果。
- **中英文**：默认中文产出；外文资料翻译后引用，同时保留原文链接。
- **控制篇幅**：单份报告正文建议不超过 2000 字，细碎数据放附录。
